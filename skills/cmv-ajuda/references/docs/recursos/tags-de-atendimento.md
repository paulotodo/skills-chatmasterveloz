# Tags de Atendimento

- **Fonte:** https://clihelper.chatmasterveloz.com/docs/tags-de-atendimento
- **Categoria:** Recursos
- **Menu:** Tags › Tags de Atendimento

---

🧩 **Tag de Atendimento** é a etiqueta utilizada para classificar o status de um **Ticket** (conversa) e serve para indicar em qual etapa do fluxo aquele atendimento se encontra.

☑️ **Fluxo de Trabalho:** organize visualmente o progresso das conversas (ex: "Aguardando Financeiro", "Em Suporte", "Pendente").

☑️ **Gestão Visual (Kanban):** transforme essas tags em colunas no quadro de gestão, permitindo arrastar os cards dos clientes entre as etapas.

![Tags de Atendimento em um Ticket](https://clihelper.chatmasterveloz.com/docs-imagem/22247-tags-atendimento-1024x390.jpg)

> **[RESUMO]**
>
> #### Resumo Prático
>
> ➡️ Acesse o menu **Tags**.
>
> ➡️ Ao adicionar ou editar uma tag, na seção “Configurações Avançadas”, defina o **Tipo de Tag**: Atendimento.
>
> ➡️ Habilite o **Kanban** nessa tag, e sua **Ordenação** para melhor organização.

## Como definir uma Tag do Tipo Atendimento

Acesse o menu → Tags > adicionar ou editar Tag

![Formulário de Tag de Atendimento](https://clihelper.chatmasterveloz.com/docs-imagem/22247-tag-atendimento-formulario.jpg)**Em "Configurações Avançadas":**

🔘 **Tipo de Tag:** selecione a opção **Atendimento**. Isso garante que a tag apareça na lista de conversas e nas opções do Kanban.

🔘 **Kanban:  
- Selecione **Habilitado** se quiser que esta tag vire uma coluna no seu quadro visual.
- Selecione **Desabilitado** se quiser que ela seja apenas uma etiqueta informativa colorida no ticket do cliente.

🔘 **Ordenação:** defina a prioridade numérica (0, 1, 2...). No Kanban, números menores aparecem primeiro (da esquerda para a direita).

## Como marcar uma Tag do Tipo Atendimento

No menu → Chats, na janela de ticket logo abaixo do nome do contato, defina quantas tags de Atendimento desejar para esse ticket.

![Como marcar uma Tag de Atendimento](https://clihelper.chatmasterveloz.com/docs-imagem/22247-tags-adicionar-chats-scaled.jpg)

## Quem visualiza cada Tag de Atendimento

🔘 **Sem dono:** a tag fica visível para todos os operadores. Tag criada por administrador ou supervisor nasce assim, valendo para a equipe toda.

🔘 **Com dono:** a tag de atendimento fica visível só para o dono — e para administradores e supervisores.

Para escolher o dono, acesse o menu **Tags**, clique em **Atribuir dono**, marque as tags na lista e clique em **Definir dono**. Na janela **Atribuir dono às tags**, escolha uma pessoa no campo **Dono**, ou **Ninguém (tag pública)**, e clique em **Aplicar**.

◽ Só as tags de atendimento mudam de visibilidade; as de CRM e de Encerramento ficam como estão.

🔘 **Tags de atendimento visíveis só para quem criou?** Fica em **Configurações → Opções**. Ligado, cada operador visualiza apenas as tags de atendimento que ele mesmo criou; as tags antigas, sem autor registrado, continuam visíveis para todos. Administradores e supervisores continuam visualizando tudo.

> **[DUVIDAS]**
>
> ### Dúvidas Comuns
>
> **Criei uma Tag de Atendimento e um atendente não a visualiza. Por quê?** A tag pode ter dono, e aí só o dono a visualiza — além de administradores e supervisores. Confira a lista do menu **Tags** e, se for o caso, use **Atribuir dono** para deixá-la como **Ninguém (tag pública)**.
>
> **Posso ter uma Tag de Atendimento que não está no Kanban?** Sim. Basta deixar o campo Kanban como "Desabilitado". Ela servirá como uma etiqueta visual colorida no chat, mas não criará uma coluna nova.
>
> **Como movo um cliente de uma tag para outra?** Se o Kanban estiver ativo, basta arrastar o card. Se não, você pode alterar a tag manualmente dentro da janela de conversa (chat).

## **Diferença de Ticket e Protocolo**

#### (Ticket)

Um **ticket** é uma conversa com um cliente dentro de uma conexão (WhatsApp, Facebook, etc.)

Ele não muda de número, mesmo que seja fechado e reaberto entre o mesmo cliente e conexão. Se a mesma pessoa usar outra plataforma, aí sim, será outro número de ticket.

#### # Protocolo

Um **protocolo** é o que acontece entre abrir e fechar um ticket. Cada vez que o ticket é reaberto, um novo protocolo é criado (mas atenção: o número do ticket continua sempre o mesmo).

**Resumindo:** o ticket é a conversa, e o protocolo são os "capítulos" dessa conversa.
